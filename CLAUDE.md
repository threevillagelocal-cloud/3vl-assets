## Gotcha: CSS escapes through the guard
The guard's restore PUT strips backslashes, so CSS like content:"97" breaks. Use the literal character in page CSS (e.g. content:"↗").

A short-SHA pin (`@c51d46b03fb8`) returned "Package size exceeded the configured limit of 50 MB" instead of the file, and jsDelivr CACHES that error for that URL. ## Instant design: BD's plain layout must never show (owner, 10/1/2026)
Owner: "I want no delay." A first-time visitor saw /blog and /events load in BD's plain layout, then switch. Fixed 10/1; keep it fixed:
- p3.js (blog, /categories, business results) and tvl-cal.js (/events, /events-calendar) no longer wait for the whole page. They start the moment `#main-content` has been read (MutationObserver), and each has a run-once guard (`window.__p3`, `window.__tvc`). Do NOT put their startup back on DOMContentLoaded or `defer` timing.
- They are loaded from the page HEAD: BD admin > Settings > Design Settings > Custom CSS / HEAD tab > "Additional HEAD Code" box. The block between `<!-- 3VL instant design` and `<!-- /3VL instant design -->` is a copy of site/head-snippet.html. It preloads the files at high priority (async scripts are low priority by default and arrive late on slow connections) and holds the hide rule (old layout stays invisible until `p3-on`/`p3-done`/`tvc-on`/`tvc-done`, and shows by itself after 6s if a file fails).
- That box is NOT reachable by the API and does not run [widget=] shortcodes. Edit it by driving the owner's Chrome: open the Custom CSS / HEAD tab FIRST (a save from another tab silently drops the change), set the CodeMirror value by JS, click that tab's Save Changes, then curl the site to confirm. Inline scripts in that box only run after BD's stylesheets load, so anything time-critical must be a preload link or an async file, not inline code.
- Because of that, the HEAD points at a fixed address that never needs editing: https://threevillagelocal-cloud.github.io/3vl-share/live/ (p3/p3.js, p3/p3.css, p3/vip_meta.json, p3/img, events-cal/tvl-cal.js, events-cal/tvl-cal.css). Widget 13 and the events page block load the same addresses. After ANY change to those files run `python site/publish_live.py` (copies them into ../3vl-share/live and pushes; live in about a minute, browsers may hold the old copy 10 minutes). There are no SHA pins for these files any more; other p3 files (today, prof, home2, etc.) are still SHA-pinned in widget 13.
- Events: 3vl-site-guard/scripts/events_sync.py writes BD's event list into the page (`#tvl-cal-feed`) so the calendar draws with no second download; tvl-cal.js still fetches /event-calendar-json and redraws only if the list changed. Rebuild the pages without posting events: `gh workflow run events-sync.yml -f mode=pages` (in 3vl-site-guard).
- Check after changes (must show the old layout for 0 ms): session tools were throwaway; the method is puppeteer + CDP throttle (3 Mbps, 80 ms, cache off) with a requestAnimationFrame probe that records whether BD's native elements (.post-search-result-count-container, .member-search-result-count-container, .search_result, .categories-panel) are visible before #p3 / #tvl-cal content is.
- Any NEW page design that rewrites a BD page must follow the same pattern (start at content-read, hide rule in the HEAD snippet) before it goes live.
